# Security / Sicherheit - TaktBoot Community 0.1.0 Build 0002

## DE

### Sicherheitsmodell

1. **Identitaet**: Version, Buildnummer, Baudatum, Vendor und Channel kennzeichnen den Stand.
2. **Integritaet**: SHA-256 prueft, ob `BOOTX64.EFI` seit der Hash-Erzeugung veraendert wurde.
3. **Authentizitaet**: Eine digitale Signatur kann bestaetigen, dass ein Build mit dem vorgesehenen privaten Schluessel signiert wurde.
4. **Schluesseltrennung**: Das oeffentliche `.cer` darf ins Community-Projekt. PFX/private Schluessel, Passwortdateien und private Key-Dateien duerfen niemals hinein.
5. **Build-Schutz**: Bereits verwendete Buildnummern werden nicht wiederverwendet und bestaetigte Builds werden nicht still ueberschrieben.
6. **Code-Trennung**: Interne TKV.OS/TaktBoot-Loaderdetails, interne BootInfo-Strukturen, Diagnose-Innereien und Golden-Build-Inhalte werden nicht in die Community-Version kopiert.
7. **Fork-Kennzeichnung**: Veraenderte Kopien duerfen nicht als offizieller TaktVibes-Build auftreten.

### SHA-256 der EFI

`build.cmd` erzeugt `SHA256SUMS.txt` erst nach erfolgreichem Linken der finalen lokalen `BOOTX64.EFI`.
`verify_hash.cmd` vergleicht den gespeicherten Wert mit dem aktuellen Datei-Hash.

Wird die EFI danach signiert oder anderweitig veraendert, ist der alte Hash nicht mehr gueltig. Der Hash muss neu erzeugt und der neue Zustand dokumentiert werden.

### Zertifikat-Fingerprint

Vorgesehene Datei:

`cert\TaktVibes_TaktBoot_Community.cer`

Der SHA-256-Fingerprint wird mit `cert\fingerprint_sha256.cmd` erzeugt und in `cert\CERTIFICATE_SHA256.txt` geschrieben.

**Transparenzhinweis:** Das konkrete `.cer` war bei der Erstellung dieses Quellpakets nicht als Datei verfuegbar. Deshalb wird kein Fingerprint erfunden. Sobald das bereits vorhandene oeffentliche Zertifikat in den `cert`-Ordner kopiert wurde, erzeugt das Skript den echten Wert.

### Signatur

`sign_release.cmd` erwartet den privaten PFX-Pfad ausserhalb dieses Projektordners. Das Skript kopiert den PFX nicht und speichert ihn nicht im Projekt.

Der Signierschritt ist optional und getrennt vom normalen Build. Ohne vorhandenen privaten Schluessel wird nicht signiert.

## EN

### Security model

1. **Identity**: version, build number, build date, vendor and channel identify the release state.
2. **Integrity**: SHA-256 shows whether `BOOTX64.EFI` changed after the hash was created.
3. **Authenticity**: a digital signature can prove that a build was signed with the intended private key.
4. **Key separation**: the public `.cer` may be included in the Community project. PFX/private keys, password files and private-key material must never be included.
5. **Build protection**: used build numbers are never reused and confirmed builds are not silently overwritten.
6. **Code separation**: internal TKV.OS/TaktBoot loader details, internal BootInfo layouts, diagnostic internals and Golden-Build contents are not copied into the Community edition.
7. **Fork labelling**: modified copies must not present themselves as official TaktVibes builds.

### SHA-256 of the EFI

`build.cmd` creates `SHA256SUMS.txt` only after successfully linking the final local `BOOTX64.EFI`.
`verify_hash.cmd` compares the stored value with the current file hash.

If the EFI is signed or otherwise modified afterwards, the old hash is no longer valid. A new hash must be generated and the new state documented.

### Certificate fingerprint

Expected file:

`cert\TaktVibes_TaktBoot_Community.cer`

The SHA-256 fingerprint is generated by `cert\fingerprint_sha256.cmd` and written to `cert\CERTIFICATE_SHA256.txt`.

**Transparency note:** The concrete `.cer` file was not available as file input while this source package was created. Therefore no fingerprint is invented. Once the existing public certificate is copied into the `cert` directory, the script generates the real value.

### Signature

`sign_release.cmd` expects the private PFX path to be outside this project directory. The script does not copy or store the PFX inside the project.

Signing is optional and separated from the normal build. Without an available private key, no signing takes place.
